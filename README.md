# 待办 基础版 (daiban-todo)

本分支为**基础版**。基础版（`cn.daiban.daiban.basic`）不含计时功能，专注版（`cn.daiban.daiban`）含正向计时、锁屏与统计；两版包名不同，可以同时安装，数据各自独立。旧版基础版 v1.5.1 与专注版曾共用包名，新基础版不会自动继承旧包的数据，请先导出再导入。

兼容 [topydo](https://github.com/topydo/topydo) / [todo.txt](http://todotxt.org) 格式的安卓待办清单（Flutter），为“按计划备考、没做完自动顺延、做完自动提前”而做。

> 许可：GNU GPL-3.0（见 [LICENSE](LICENSE)）。todo.txt 格式与任务语义（优先级、`due:`、`t:`、`x` 完成前缀、`+项目`/`@情境`）参考自 topydo

## 功能

- **导入 / 导出**：todo.txt 文件、分享 / “用待办打开”、粘贴文本；**.ics 日历**直接导入（自动把“一天一条”的事件拆成“一项一条”任务）；导出 todo.txt / done.txt / .ics。导入时「追加」保留现有任务（完全相同的行自动跳过）；「覆盖」只替换导入数据中出现的那些类别的待办，已完成一律保留，其它类别原样保留。导入文件里的已完成行若与现有完全相同则跳过，否则追加。
- **检查更新**（可选，不强制）：启动后在后台查询本仓库里本版本的 GitHub Release；发现新版本时出现可关闭提示，可点「稍后」继续使用。关于页也可手动检查。只有你点「更新」才会下载对应架构的 APK，并仍要通过系统安装确认，不会静默安装。专注版与基础版互不混用，不会把 GitHub Latest（专注版）当成基础版更新。
- **三个视图**：今日（今天 + 逾期，未到 `t:` 开始日期的不显示；默认按时间排列，右上角可改为按类别分组，类别内仍按时间，类别可折叠）、全部任务（同样支持按时间 / 按类别，类别可折叠）、已完成（done.txt 归档）。
- **按类别独立提前 / 顺延**：类别 = 任务的第一个 `+标签`（如 `+408`、`+数学`）。
  - *完成即提前*：某类别今日任务（含逾期）全部完成后，只让该类别的下一批提前显示到今天（不改写任务的截止 / 开始日期）；每个类别标题上还有手动“提前下一批”按钮。
  - *整体顺延*：跨天后，某类别昨天还有未完成任务，只把该类别后续未完成任务的 `due`/`t` 各推迟 1 天（打开 / 回到前台时检查，无需后台服务）。
  - 全局开关 + 每个类别单独开关（跟随全局 / 开 / 关）。
- **提前可还原**：某类别今日任务全部完成后，只让下一日期批次提前显示在今日，所有任务的 `due:` / `t:` / `plan:` 保持不变，日期标签仍显示原计划日，额外标注“提前显示 · 日期不变”。当天取消完成较早批次的任务，会撤回其后批次的提前显示；完成后再取消完成、重启和组件后台操作使用同一规则。显示记录写在隐藏标签 `pv:YYYYMMDD.序号.间隔` 中；跨日保留显示，不会因提前显示就认定任务逾期。旧数据中仍有 `pf:` 的按确切记录恢复被平移的 due/t 并迁移；没有记录的历史改动不猜测日期。
- **预计完成**（仅应用内，桌面组件不显示）：今日页每个类别标题下一行小字显示“进度 已完成/总数 · 计划 · 预计（提前/落后 N 天）”，「批量管理」里的类别列表显示更详细的说明。按“量”来算，不看速度：每条任务导入/新增时会记下原计划日期，写在隐藏标签 `plan:YYYY-MM-DD` 里（界面和编辑框不显示，完成后保留；“完成即提前”只改显示，“整体顺延”仍改写 `due:`/`t:`，都不改 `plan:`；老数据首次加载时补写，有 `pf:` 记录的按其还原）。同一原计划日的任务算“一天的量”，这一天的任务全部完成才算完成一天，只做一部分不算。提前天数 = 原计划日在今天之后且已全部完成的天数 − 原计划日在今天之前但没做完的天数；计划完成 = 原计划最后一天；预计完成 = 计划完成 − 提前天数（落后则为 + 落后天数）。手动编辑任务日期或「批量平移」视为重新计划，`plan:` 随之更新。
- **批量管理**：删除全部、清空已完成、按类别删除 / 重命名合并 / 平移该类别未完成任务的日期；列表里长按进入多选，批量完成 / 删除 / 更改类别 / 平移日期；绝大多数操作可撤销（一步）。
- **桌面组件**：把「待办 · 今日」放到主屏幕（默认 2×2，可横向/纵向调整大小）。按类别列出今天未完成的任务，点勾选框即可完成（不必打开应用，完成规则和按类别提前与应用内一致）；点标题打开应用。
- 新增 / 编辑 / 删除任务，优先级，开始日期，中文界面，数据存在应用私有目录的 `todo.txt` / `done.txt`。

## 导入格式

### todo.txt（每行一条，UTF-8）

```
(A) 数据结构 KMP 手算 next/nextval（p117-118） +408 +数据结构 due:2026-11-11 t:2026-11-11
数学 极限与连续习题 +数学 due:2026-11-12 t:2026-11-12
x 2026-11-10 背单词 +英语 due:2026-11-10
```

- `(A)` 优先级；`x 完成日期 …` 表示已完成；`+项目`、`@情境` 标签；
- `due:YYYY-MM-DD` 截止日期，`t:YYYY-MM-DD` 开始日期（通常未到这天不出现在“今日”；提前显示的批次例外，原日期不变）；也支持 `due:明天`、`due:3d`、`t:+1w` 这类相对日期；全角冒号 / 括号会自动规整；
- **类别** 是第一个 `+标签`。导入时会弹出对话框，可以把类别设为某个名字（成为第一个 `+标签`），并选择保留或清除原有其它标签。

### .ics 日历

- 支持 `VEVENT` 的 `DTSTART` / `DTEND`（DATE 与 DATE-TIME，`DTEND` 不含当天），行展开，`\n \, \;` 转义，多日事件按天展开；
- 默认类别取日历名 `X-WR-CALNAME` 的第一个词；`SUMMARY` 第一个词作为科目标签；
- `DESCRIPTION` 会按 “；”“。”、上午/下午、“，”“、”拆成一项一条的学习任务（页码 `pXX-YY` 与【重点】标记跟随所在条目），逻辑见 `lib/logic/plan_splitter.dart`；
- 命令行转换：`dart run tool/ics_to_todo.dart 输入.ics 输出.txt`。

| `数据结构_串起_细化到页.txt` | 《2027年数据结构考研复习指导》第 4 章（p109）到第 8 章（p390），合并相关小节、试题+答案合为一项，34 项任务（每项约 1 小时、6~12 页）分配到 11 天，细化到页 |

## 添加桌面组件

1. 先打开一次「待办」并导入或添加任务（这样组件才能拿到今日列表，并注册后台勾选回调）。
2. 长按桌面空白处 → 选择「微件 / 小组件 / Widgets」→ 找到「待办」→ 把「待办 · 今日」拖到桌面。部分系统也可以长按应用图标，再选「微件」。
3. 默认大小为 2×2 格，可拖边框或双指缩放，横向、纵向都能调。
4. 点标题打开应用；点任务左侧勾选框即可完成该条。完成后若该类别今天已经没有未完成任务，会按设置自动提前下一批。

## 构建

需要 Flutter 3.35+、JDK 17、Android SDK（platform 34+）。

```bash
python3 tool/gen_icons.py          # 生成启动图标（需要 pillow；仓库不含二进制图标）
flutter pub get
flutter analyze
flutter test
flutter build apk --release --split-per-abi --target-platform android-arm64,android-arm
```

产物在 `build/app/outputs/flutter-apk/`，默认使用调试证书签名，可直接侧载；要上架请自行配置签名密钥（不要把密钥提交进仓库）。
GitHub Actions（`.github/workflows/release.yml`）可手动触发，自动构建并把 APK 发布到 Release。

## 已知限制

- 不支持 topydo 的 `rec:` 重复任务、依赖、子任务；这些标签会原样保留但不生效。
- 没有通知提醒。跨日顺延会在打开 / 回到前台时执行，桌面组件也会在大约 0:01 或最多约 30 分钟的周期刷新时触发一次。勾选组件后需等后台任务跑完（约一两秒）才会刷新列表。
- 撤销只保留上一步。
